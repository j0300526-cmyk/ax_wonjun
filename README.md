# MaterialSwitch AI

> 공급망 충격 대응형 대체 원료 승인·조달 운영 시스템

MaterialSwitch AI는 Corevia가 특정 공급사에 의존하는 원료의 공급 중단이나 납기 지연을 감지했을 때, 대체 원료 후보를 평가하고 품질 담당자의 승인을 거쳐 발주 요청·생산계획·Masil 캠페인 일정까지 갱신하는 의사결정 워크플로입니다.

- 프로젝트 주제: **04. 대체 원료 검토와 사용 승인**
- 데모 앱: [ax-wonjun-ysln.axhub.page](https://ax-wonjun-ysln.axhub.page)
- 배포 조직: `lounge`
- 저장소: [j0300526-cmyk/ax_wonjun](https://github.com/j0300526-cmyk/ax_wonjun)

## 1. 어떤 문제를 해결하나요?

대체 원료 검토는 단순히 값싼 공급사를 추천하는 문제가 아닙니다. 공급 차질이 발생하면 조달·품질·생산·마케팅 부서가 서로 다른 자료와 기준으로 판단하기 때문에 다음과 같은 병목이 생깁니다.

1. 공급 지연이 실제 생산과 판매 일정에 미치는 영향을 즉시 알기 어렵습니다.
2. 후보의 가격·납기·품질·공급 안정성을 따로 검토해 비교 근거가 흩어집니다.
3. 시험자료가 빠진 후보가 승인 검토로 넘어갈 수 있습니다.
4. 품질 승인 후에도 발주 요청, 생산계획 변경, 다른 부서 안내가 수작업으로 남습니다.
5. 어떤 데이터와 가정으로 누가 결정했는지 추적하기 어렵습니다.

제공 데이터에서는 `M-B`가 해외 공급사 `V-205`에 의존하며 독점 조건을 갖습니다. 이 원료가 사용되는 제품군은 Masil의 `SKU-1001`~`SKU-1004`와 연결되고, 2026-06-30 재고 스냅샷의 최저 재고 커버는 `SKU-1004`의 2.2주입니다. 따라서 원료 공급 충격은 Corevia 생산뿐 아니라 Masil 입고·캠페인 일정에도 영향을 줄 수 있습니다.

## 2. 어떻게 해결하나요?

```text
공급 충격 입력
    ↓
재고·비용·캠페인 영향 재계산
    ↓
대체 원료 후보 다기준 평가
    ↓
필수 증빙 관문(Evidence Gate)
    ↓
품질 사용 승인권자의 승인 또는 거절
    ↓
발주 요청 + 생산계획 + Masil 일정 작업 생성
    ↓
상태와 의사결정 근거 기록
```

### 공급망 스트레스 테스트

사용자는 다음 두 조건을 직접 바꿀 수 있습니다.

- 기존 공급사의 납기 지연: 0~45일
- 공급 가능 물량: 20~100%

앱은 데이터룸의 SKU별 현재고, 최근 4주 판매량, 발주일·리드타임·발주액을 사용합니다. 데이터룸은 실제 기업 기록이 아닌 **가상 기록**입니다. 입력 지연과 충족률은 사용자 가정입니다.

```text
주간 수요 = 2026-06-30 이전 최근 4주 판매량 평균
재고 커버일 = 현재고 ÷ (주간 수요 / 7)
예정 도착일 = 발주일 + 기록된 리드타임(주) × 7일 + 시나리오 지연일
보충 전 재고 노출일 = max(0, ceil(예정 도착까지 남은 일수 - 재고 커버일))
미공급 발주액 = Σ(발주액 × (1 - 시나리오 충족률 / 100))
```

노출일은 **실제 품절 예측이 아닙니다**. 데이터에 운송중 재고의 도착일이 없어 이를 제외했으며, 다른 입고·생산일정도 확정할 수 없습니다. 미공급 발주액은 계약금액의 시나리오상 미충족분이지 긴급조달 추가비용이나 손실액이 아닙니다. 캠페인 지연일도 산정하지 않습니다.

### 대체 후보 평가 보류

Ho·Xu·Dey(2010)는 공급사 선택에 다기준 평가가 필요함을 정리합니다. 그 논문은 이 회사에 적용할 보편적 가중치 40/25/15/20을 제공하지 않습니다. 데이터룸에는 ALT-B1~B3의 실측 품질·납기·견적이 없으므로 가중 점수와 추천 순위를 **산정하지 않습니다**. 후보 카드는 시연용 자리표시자입니다. 화면의 질문 응답 역시 생성형 AI가 아니라 명시적 규칙입니다.

실제 후보 비교를 하려면 규격·시험 결과, 검증된 납기와 견적, 복수 조달 가능 여부를 확보하고 승인권자와 평가 기준 및 가중치를 정해야 합니다. 품질 적합성은 점수 보상으로 상쇄하기보다 승인 전 필수 관문으로 둡니다.

### 증빙 관문과 사람 승인

다음 필수 자료가 모두 확인돼야 승인 버튼이 활성화됩니다.

- 성분·규격 비교표
- 품질 시험 결과
- 규제·안전성 검토
- 샘플 생산 결과

하나라도 누락되면 상태가 `증빙 보완 필요`로 남고 사용 승인이 차단됩니다. 공급처 현장 확인은 프로젝트의 추가 확장 항목으로 다룹니다.

### 승인 이후 모의 처리

화면에서 **모의 승인**하면 다음 세 업무가 브라우저 저장소에 생성됩니다.

1. 조달팀: 대체 원료 발주 요청
2. 생산팀: `PL-02` 생산계획 갱신
3. Masil 운영팀: `SKU-1001`~`SKU-1004` 입고·캠페인 일정 검토

승인 거절 시에는 품질팀의 보완 시험·다른 후보 검토 작업을 모의 생성합니다. 입력과 이력은 해당 브라우저의 localStorage에만 남으며 실제 발주·생산계획이나 불변 감사기록을 변경하지 않습니다.

## 3. 과제 완료 조건 대응

| 완료 조건 | 구현 내용 |
| --- | --- |
| 실제로 돌아가는 시연 시스템 | 조건 입력 → 기록 기반 노출 계산 → 모의 증빙·승인 → 브라우저 내 작업 생성 |
| 세 가지 상황 시연 | 정상, 15일 지연 또는 공급량 50%, 증빙 누락/승인 거절 |
| 나만의 확장 | 공급망 스트레스 테스트와 공급처 현장 확인 상태 |
| 다른 부서 영향 | Corevia 결정이 Masil 일정 검토 작업을 모의 생성 |
| 기록과 가정 구분 | 화면에 `가상 기록`, `재계산`, `모의` 배지 표시 |

## 4. 시연 방법

### 상황 1 — 정상 승인

1. `정상 · 기본 조건`을 선택합니다.
2. 후보별 실측 자료가 없어 점수를 매기지 않는 상태를 확인합니다.
3. 필수 증빙이 모두 확인된 상태에서 `승인 및 후속 처리`를 누릅니다.
4. 승인·후속 작업 화면에서 조달·생산·Masil 작업 3건을 확인합니다.

### 상황 2 — 조건 변경

1. `조건 변경 · 15일 지연` 또는 `물량 50%`를 선택합니다.
2. 보충 전 재고 노출일과 미공급 발주액이 어떻게 달라지는지 확인합니다.
3. 대체 후보를 선택하고 재승인 흐름을 진행합니다.

### 상황 3 — 정보 부족 또는 승인 거절

1. `예외 · 증빙 누락`을 선택합니다.
2. 품질 시험 결과와 샘플 생산 결과가 빠져 승인 버튼이 비활성화되는지 확인합니다.
3. 자료를 보완하거나 `승인 거절`을 누릅니다.
4. 보완 시험·다른 후보 검토 작업과 감사 이력을 확인합니다.

## 5. 데이터 출처와 한계

`01_참가자_배포용/04_원본데이터/README.md`는 모든 데이터가 **가상**이라고 명시합니다. 아래 파일의 값을 사용해 시연 시나리오를 구성했으며 실제 기업 실적으로 계수를 추정하지 않았습니다.

주요 근거 파일:

- `01_corevia/master/m_material_cv.csv`
- `01_corevia/procurement/procurement_material_purchase_cv.csv`
- `01_corevia/procurement/material_lot_master_cv.csv`
- `01_corevia/production/production_material_consumption_cv.csv`

- `02_masil/master/m_sku_ms.csv`
- `00_common/calculation_definitions.md`
- 데이터 이용 기준 `A05.html`

중요한 데이터 한계:

- 원료 입고량과 생산 소비량은 집계 시점과 수량 기준이 일치하지 않습니다.
- 따라서 두 파일을 단순 차감해 절대 원료 재고를 만들지 않습니다.
- 대체 원료 후보 규격·시험·규제 증빙과 공식 승인 절차는 원본에 없습니다.
- 운송중 재고의 입고 예정일이 없어 실제 품절일이나 캠페인 지연일을 예측할 수 없습니다.
- 후보 `ALT-B1`~`ALT-B3`, 시험 결과, 승인 흐름은 시연용 가정·모의 회신으로 명시합니다.
- Celtonic은 인수 검토 대상이지 즉시 사용 가능한 대체 공급처로 간주하지 않습니다.

## 6. 연구와 산식의 관계

- **재고 커버**: 데이터룸의 `calculation_definitions.md` 1.3을 그대로 따릅니다.
- **재고와 발주 도착 비교**: 재고에서 수요를 차감하고 발주 도착을 고려하는 재고 흐름 원칙을 적용합니다. 논문이 특정 지연·비용 계수를 제공한다고 주장하지 않습니다.
- **다기준 공급사 선택**: Ho·Xu·Dey의 검토를 기준 항목 선정의 참고로만 사용합니다. 후보 데이터가 없어 가중치·점수를 계산하지 않습니다.
- **회복력**: Hosseini·Barker의 연구는 회복력을 평가할 필요성을 뒷받침하지만, 이 데모에 베이지안 네트워크를 구현하거나 논문의 계수를 이식한 것은 아닙니다.

참고 논문:

- [재고 흐름에서 입고량·수요량을 분리한 모델](https://www.sciencedirect.com/science/article/abs/pii/S0925527313004568) — 본 구현의 접근 방향 참고. 해당 논문의 예측 모형을 이식한 것은 아님.
- Hosseini & Barker, [A Bayesian network model for resilience-based supplier selection](https://doi.org/10.1016/j.ijpe.2016.07.007)
- Ho, Xu & Dey, [Multi-criteria decision making approaches for supplier evaluation and selection](https://doi.org/10.1016/j.ejor.2009.05.009)

## 7. 기술 구성

현재 버전은 Node 빌드가 정적 자산 경로를 생성하는 웹앱입니다.

```text
index.html       화면 구조
modules/         기록 기반 산식, 화면 렌더링, 시연 상태
scripts/         원본 CSV 대조 및 정적 자산 빌드
axhub.yaml       AXHub 정적 배포 설정
README.md        문제·해결·시연·데이터 설명
01_참가자_배포용/  제공 가상 데이터룸(수정하지 않음)
```

- 상태 저장: 브라우저 `localStorage`
- 외부 API와 환경변수: 없음
- 배포 방식: AXHub static
- 정적 출력 위치: `dist` (자산 파일은 내용 기반 경로)

### 프론트엔드 디자인 원칙

프론트엔드의 인터랙션과 모바일 디테일은 [Emil Kowalski의 Skills for Designers and Engineers](https://github.com/emilkowalski/skills)에서 다음 원칙을 참고했습니다.

- 버튼은 누르는 순간 `scale(0.97)`로 반응하고 100~160ms 안에 복귀
- 진입·상태 변화에는 강한 `ease-out`을 사용하고 반복 동작에는 불필요한 애니메이션을 넣지 않음
- `prefers-reduced-motion` 사용자의 이동 애니메이션 제거
- 터치 장치에서 고착되는 hover와 탭 하이라이트 제거
- `100dvh`, safe-area, 44px 터치 영역으로 모바일 조작감 보강
- 숫자 변화에는 고정 폭 숫자를 사용해 레이아웃 흔들림 방지
- 긴 업무명·식별자와 좁은 표에서 넘침이 발생하지 않도록 방어

디자인을 복제한 것이 아니라 해당 저장소의 설계 원칙을 MaterialSwitch AI의 업무 화면에 맞게 적용했습니다.

로컬 실행:

```bash
npm test
npm run build
python -m http.server 4173 --directory dist
```

브라우저에서 `http://localhost:4173`을 엽니다.

## 8. 현재 한계와 다음 단계

현재 버전은 심사 시연을 위한 프론트엔드 프로토타입입니다. 브라우저별로 상태가 저장되며 실제 회사 발주나 승인을 전송하지 않습니다.

다음 단계에서는 다음을 구현할 수 있습니다.

1. AXHub DB를 사용한 사용자 간 업무·감사 이력 공유
2. CSV 업로드와 원본 데이터 자동 검증
3. 역할별 로그인과 승인 권한 관리
4. 후보별 실제 시험 증빙 파일 연결
5. 생산계획·발주 시스템 커넥터 연동
6. 스트레스 계산식의 공식 업무 규칙화 및 민감도 검증

## 9. 안전 원칙

- AI가 원료 안전성이나 사용 가능성을 독자적으로 확정하지 않습니다.
- 필수 증빙이 없으면 승인 단계를 차단합니다.
- 원본 사실, 계산 결과, 참가자 가정을 항상 구분합니다.
- 실제 외부 발주·메일·승인 대신 모의 작업을 생성합니다.
- 데이터 한계를 숨기지 않고 화면과 문서에 함께 표시합니다.
